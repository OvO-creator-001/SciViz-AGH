# 内容分类规范

## 分类表

| 编号 | 分类 | 允许内容 | 禁止混入 |
|---:|---|---|---|
| 01 | `docs/governance/` 治理与交接 | 规则、ADR、责任边界、交接清单 | 产品方案、源码、生成产物 |
| 02 | `docs/product/` 产品与需求 | 项目规划、用户故事、范围、验收标准 | 实现代码、论文全文 |
| 03 | `docs/research/` 研究与依据 | 合法可存储的论文笔记、链接、实验与竞品结论 | 无授权论文原文、运行产物 |
| 04 | `docs/architecture/` 架构与接口 | 系统设计、API、Schema、威胁模型、技术 ADR | 产品宣传、测试输出 |
| 05 | `src/` 源代码 | 运行时源码、模块内必要资源 | 日志、模型输出、秘密信息 |
| 06 | `tests/` 测试与验证 | 测试代码、测试夹具、小型固定期望值 | 临时输出、生产密钥 |
| 07 | `examples/` 示例与演示 | 可公开的样例、教程、演示配置 | 真实用户数据、不可再分发内容 |
| 08 | `evidence/` 证据与产物 | 报告、trace、模型/页面清单、哈希与复现证据 | 未说明来源的大文件、缓存 |
| 09 | `ops/` 运维与复现 | 构建、部署、环境模板、复现工具 | 实际 `.env`、凭据、个人配置 |
| 10 | `releases/` 不可变版本 | 已交接版本的清单与快照 | 日常开发、对旧版的任何改写 |
| 11 | `changes/` 技术更新日志 | 每次 PR 独立且不可覆盖的技术条目 | 泛泛而谈的提交说明 |

GitHub 协作自动化目录不计入产品内容分类。根目录只保留全仓库入口文件，例如 README、CHANGELOG、package.json、许可证和构建入口。

## 判定顺序

1. 文件是否属于治理或决策？放 `docs/governance/`。
2. 是“做什么/为什么”还是“如何实现”？前者放 `docs/product/`，后者放 `docs/architecture/`。
3. 可执行实现放 `src/`，验证实现放 `tests/`，可复制用法放 `examples/`。
4. 运行后产生、用于证明结果的内容放 `evidence/`；可丢弃的缓存不提交。
5. 正式交接副本只能由版本流程写入 `releases/`。

## 文件命名

- 文档：`UPPER_SNAKE_CASE.md` 或稳定的主题名。
- 变更条目：`YYYYMMDD-HHMM-kebab-case.md`。
- 版本目录：`vMAJOR.MINOR.PATCH`。
- 生成产物：`主题-v版本-短哈希.扩展名`。
- 文件名不得包含“最终版”“最新版”“new”“final2”等含糊版本词。
